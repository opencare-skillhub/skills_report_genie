# 医学文件处理工作流 - 重新设计

**版本**: 2.0 (重新设计)  
**日期**: 2024-01-19  
**核心改变**: 从"先分类后解析"改为"先解析后分类"

---

## 问题分析 (v1.0 的问题)

### ❌ 旧流程的问题

```
问题: 直接根据混乱的文件名来分类
原流程:
  1. 扫描目录中的混乱文件
  2. 根据文件名分类
  3. 创建目录
  4. 移动文件
  5. 逐个解析文件

风险:
- 文件名不规范，分类错误率高
- 解析后发现文件被误分类，需要重新移动
- 无法根据实际内容纠正分类
- JSON 数据分散，难以汇总
```

---

## 新设计流程 (v2.0)

### ✅ 正确流程

```
第一步: 扫描并解析所有文件
  ↓
第二步: 基于提取内容，重命名所有文件
  ↓
第三步: 更新 JSON 文件（单个 + 汇总）
  ↓
第四步: 读取新文件名中的分类信息
  ↓
第五步: 创建目录并分类移动文件
```

---

## 详细步骤

### 第一步: 扫描并解析

```
输入: 混乱的目录
  ├── 某某检查.jpg
  ├── 病情_页面01.JPG
  ├── IMG_0125.JPG
  ├── ct扫描.pdf
  └── ...

逻辑:
1. 扫描所有文件 (图片、PDF、Word、Excel)
2. 逐个调用 parse_single_image.py 解析
3. 提取关键信息:
   - report_date: YYYY-MM-DD
   - report_type: 报告类型 (CT、血检、病理等)
   - diagnosis: 诊断简述
   - patient_id: 患者ID (可选)
   - sequence: 序列号 (多页文档)

输出: 每个文件生成
  ├── file_hash_result.json (完整提取结果)
  └── file_hash_data.json (结构化数据)
```

### 第二步: 标准化重命名

```
重命名规则:
  <date>_<type>_<digest>_<sequence>.<ext>

示例转换:
  IMG_0125.JPG
  → 2024-09-05_CT_病灶标注_001.jpg

  某某检查.jpg
  → 2023-06-27_PET-CT_肿瘤标志物_001.jpg

  病情_页面01.JPG
  → 2023-06-23_病历_诊断描述_001.jpg

字段说明:
  - <date>: 报告日期 (YYYY-MM-DD)
  - <type>: 报告类型
    * CT / MRI / 超声 / X光
    * 血检 / 病理 / 遗传 / 病历
    * 处方 / 心理 / 营养 / 并发症
  - <digest>: 内容摘要 (关键诊断/指标信息)
  - <sequence>: 序列号 (多页文档分别编号)
  - <ext>: 原扩展名
```

### 第三步: 更新 JSON

```
单个文件 JSON 结构:
  {
    "original_name": "IMG_0125.JPG",
    "standard_name": "2024-09-05_CT_病灶标注_001.jpg",
    "file_hash": "abc123def456...",
    "extraction_result": {
      "confidence": 0.98,
      "report_date": "2024-09-05",
      "report_type": "DICOM CT",
      "diagnosis": "疑似胰腺或腹膜后病变",
      "summary": "腹部CT显示特定区域异常...",
      "indicators": [...],
      "findings": "腹部横断面CT图像..."
    }
  }

保存位置:
  data/extracted/
    ├── 2024-09-05_CT_病灶标注_001.json
    ├── 2023-06-27_PET-CT_肿瘤标志物_001.json
    └── ...

汇总 JSON (主病情文件):
  patient_summary.json
  {
    "patient_id": "hash_xxx",
    "date_processed": "2024-01-19T10:30:00Z",
    "total_files": 50,
    "files": [
      {
        "standard_name": "2024-09-05_CT_病灶标注_001.jpg",
        "category": "imaging",
        "confidence": 0.98,
        ...
      }
    ],
    "timeline": {
      "2024-09-05": [CT影像],
      "2023-06-27": [PET-CT],
      ...
    },
    "summary_by_type": {
      "imaging": [...],
      "lab_reports": [...],
      ...
    }
  }
```

### 第四步: 基于文件名分类

```
分类规则 (从新文件名中读取):
  
新文件名格式: <date>_<type>_<digest>_<sequence>.<ext>

分类逻辑:
  if <type> in ['CT', 'MRI', '超声', 'X光']:
    category = IMAGING
  elif <type> in ['血检', '病理', '遗传', 'NGS']:
    category = LAB_REPORTS
  elif <type> in ['病历', '诊断']:
    category = MEDICAL_RECORDS
  elif <type> in ['处方']:
    category = PRESCRIPTIONS
  elif <type> in ['心理']:
    category = PSYCHOLOGY
  elif <type> in ['营养']:
    category = NUTRITION
  else:
    category = OTHER

优势:
✓ 100% 正确 (基于实际提取的内容)
✓ 无需重新读取文件内容
✓ 直接从文件名判断分类
```

### 第五步: 创建目录并移动

```
目录结构创建:
  reports/
  ├── imaging/          # 影像检查
  │   ├── CT/
  │   ├── MRI/
  │   └── ultrasound/
  ├── lab_reports/      # 检验报告
  │   ├── blood_tests/
  │   ├── pathology/
  │   └── genetic/
  ├── medical_records/  # 病历记录
  ├── prescriptions/    # 处方用药
  ├── psychology/       # 心理支持
  ├── nutrition/        # 营养管理
  └── other/

文件移动:
  原文件: <source>/IMG_0125.JPG
  新位置: reports/imaging/CT/2024-09-05_CT_病灶标注_001.jpg
  
  重命名后:
    reports/imaging/CT/
      ├── 2024-09-05_CT_病灶标注_001.jpg
      ├── 2024-09-05_CT_病灶标注_001.json
      ├── 2023-08-15_CT_肿瘤大小_001.jpg
      └── 2023-08-15_CT_肿瘤大小_001.json
```

## 实现模块


## 错误处理

```
可能的错误和处理:

1. OCR 识别失败
   → 保留原文件，标记为 "unprocessed"
   → 人工审核清单

2. 日期格式不统一
   → 自动转换为 YYYY-MM-DD
   → 无法识别 → 使用文件修改时间

3. 报告类型未知
   → 分类到 "other" 目录
   → 人工审核

4. 重复文件
   → 基于 file_hash 检测
   → 保留最新版本，删除重复
   → 记录在日志中

5. 文件移动失败
   → 记录错误
   → 继续处理其他文件
   → 生成失败清单
```
